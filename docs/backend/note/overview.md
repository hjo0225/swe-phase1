# Note Domain — Overview

## 목적

사용자가 고른 **보관함(Vault) 폴더 안의 Markdown 노트와 폴더**, 그리고 노트 사이의 참조를 관리한다. 명세서의 **Basic(Note CRUD)**, **Major 2(검색·연결·내용 가져오기)**, 사용자 요청인 **보관함·폴더**(D-14)를 담당한다.

## 소유

- 보관함 열기·전환, 최근 보관함 목록
- 노트 생명주기: 생성, 조회, 저장(자동 저장), 이름 변경, 삭제 — 노트 = `.md` 파일
- 폴더: 만들기, 이름 변경, 삭제, 목록(트리) — 폴더 = 실제 폴더
- 본문 파생 데이터: 검색용 텍스트, `[[링크]]` 대상 (D-15)
- 색인(SQLite): 파일에서 다시 만들 수 있는 검색·링크·노트 ID 표
- 외부 변경 감지: 다른 앱이 보관함 파일을 바꾸면 색인을 갱신하고 화면에 알린다
- 키워드 검색, 링크/백링크 조회, 이름 변경 시 링크 고치기

## 소유하지 않음

- 편집기 동작, Markdown ↔ 편집기 문서 변환 → Renderer
- AI 변환과 Pending Mark의 의미 → assist (note는 `<span data-ai-pending>`를 본문 일부로 저장만 한다)
- 인포그래픽 구조 → visualization (note는 ```` ```blink-infographic ```` 블록을 본문 일부로 저장만 한다)

## 핵심 설계 결정

1. **파일이 원본, SQLite는 색인** (D-14). 보관함을 열 때 파일을 훑어 색인을 맞추고, 색인이 사라져도 다시 만든다. AI Job만 색인 DB에 있는 유일한 비파일 데이터다(잃어도 원문은 안전하다).
2. **노트 ID는 색인이 부여하는 UUID**다. 경로는 바뀔 수 있으므로(이름 변경·이동) 화면과 AI Job은 ID로 노트를 가리킨다. Blink 안에서 한 이름 변경은 ID를 유지하고, 다른 앱에서 한 이름 변경은 삭제+생성으로 보인다.
3. **제목 = 파일 이름** (D-16). 제목 입력은 입력을 마칠 때(Enter·포커스 이동) 파일 이름을 바꾼다 — 글자마다 파일 이름을 바꾸지 않는다.
4. **본문은 Markdown 문자열**로 주고받는다. Main은 Markdown을 해석해 검색용 텍스트와 링크 대상만 뽑는다. 편집기 문서 변환은 Renderer가 한다.
5. **링크는 본문에서 파생된다** (D-02 원칙 유지). `[[이름]]`의 대상은 조회 시점에 해석한다 — 대상 노트가 나중에 생겨도 링크가 살아난다(옵시디언 방식).

## 용어

| 용어 | 정의 |
| --- | --- |
| 보관함(Vault) | 사용자가 고른 폴더. 그 안의 `.md` 파일 전체가 노트 모음이다 |
| 노트 경로 | 보관함 기준 상대 경로, `/` 구분 (`프로젝트/회의록.md`) |
| 노트 이름 | 파일 이름에서 `.md`를 뺀 것 = 제목 |
| 링크 대상(target) | `[[...]]` 안의 텍스트. 이름 또는 확장자 없는 경로(`프로젝트/회의록`) |
| 색인 | 보관함마다 하나인 SQLite DB. 노트 ID·경로·검색 텍스트·링크 대상·AI Job |
| 숨김 폴더 | `.`으로 시작하는 폴더(`.git`, `.obsidian` 등)와 `node_modules`. 노트로 보지 않는다 |
