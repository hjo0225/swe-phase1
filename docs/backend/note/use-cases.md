# Note Domain — Use Cases

Actor는 모두 **사용자**(Renderer를 통해). Renderer만의 동작은 "Renderer"로 표시한다.

---

## 보관함

### UC-VAULT-001 보관함 열기

- **Trigger:** 앱 시작(마지막 보관함 자동), 보관함 선택 화면의 `폴더 열기`/`최근 보관함`, Sidebar의 `보관함 전환`
- **Main Flow:**
  1. (`폴더 열기`) Main이 폴더 선택 Dialog를 띄운다. 빈 폴더를 고르면 새 보관함이 된다.
  2. 폴더가 존재하고 읽고 쓸 수 있는지 확인한다.
  3. 이 보관함의 색인 DB를 열고(없으면 만든다) 마이그레이션한다.
  4. **색인 맞추기(UC-VAULT-002)**, 중단된 AI Job 정리(UC-ASSIST-006).
  5. 외부 변경 감시를 시작한다.
  6. 최근 보관함 목록 맨 앞에 기록한다.
- **Failure:** `VAULT_NOT_FOUND`(폴더가 사라짐 — 최근 목록에서 표시), `VAULT_NOT_ACCESSIBLE`
- **Postconditions:** 이전 보관함은 닫힌다(감시 중지, DB 닫기). Renderer는 모든 노트 캐시를 버리고 새로 읽는다.

### UC-VAULT-002 색인 맞추기

- **Trigger:** 보관함 열기, 외부 변경 감지
- **Main Flow:** 보관함의 모든 `.md` 파일(숨김 폴더 제외)을 훑어, 크기·수정 시각이 색인과 다른 파일만 다시 읽어 검색 텍스트·링크 대상을 갱신한다. 새 파일은 새 ID를 받는다. 색인에만 있는 노트는 지운다(그 노트의 AI Job도 함께).
- **Business Rules:** BR-VAULT-01

## 노트

### UC-NOTE-001 노트 생성

- **Trigger:** `+ 새 노트`(선택한 폴더 안, 없으면 보관함 맨 위)
- **Main Flow:** 폴더에 `제목 없음.md`를 만든다. 이미 있으면 `제목 없음 1.md`, `제목 없음 2.md`… 색인에 넣고 노트를 반환한다.
- **Business Rules:** BR-NOTE-01

### UC-NOTE-002 노트·폴더 목록 조회

- **Main Flow:** 보관함의 폴더 트리와 노트 요약(ID, 이름, 경로, 미리보기, 수정 시각)을 반환한다. 폴더 → 이름순, 노트 → 이름순. (최근 수정순 목록은 "최근" 보기에서 쓴다.)

### UC-NOTE-003 노트 상세 조회

- **Main Flow:** 파일을 읽어 ID·이름·경로·Markdown 본문·시각을 반환한다.
- **Failure:** `NOTE_NOT_FOUND` (파일이 사라졌으면 색인에서도 지운다)

### UC-NOTE-004 본문 저장 (자동 저장)

- **Trigger:** Renderer 편집 후 debounce, AI 결과 적용 후, 링크 삽입·내용 가져오기 후
- **Main Flow:**
  1. 노트를 찾는다. 본문이 파일 내용과 같으면 아무것도 하지 않는다.
  2. 파일에 쓴다(임시 파일에 쓴 뒤 교체 — 쓰는 도중 중단되어도 원본이 깨지지 않는다).
  3. 검색 텍스트·링크 대상을 다시 뽑아 색인을 갱신한다. 자기가 쓴 변경은 외부 변경으로 보지 않는다.
- **Failure:** `NOTE_NOT_FOUND`, `NOTE_CONTENT_TOO_LARGE`, `NOTE_WRITE_FAILED`

### UC-NOTE-010 노트 이름 변경

- **Trigger:** 제목 입력을 마침(Enter·포커스 이동)
- **Main Flow:**
  1. 새 이름을 검사한다(BR-NOTE-01). 같으면 아무것도 하지 않는다.
  2. 같은 폴더에 같은 이름이 있으면 거절한다.
  3. 파일 이름을 바꾸고 색인의 경로를 갱신한다(ID 유지).
  4. **이 노트를 가리키던 링크를 고친다**: 다른 노트의 `[[옛 대상]]`·`[[옛 대상|별칭]]` 중 이 노트로 해석되던 것을 새 대상으로 바꿔 파일에 쓴다.
- **Failure:** `NOTE_TITLE_INVALID`, `NOTE_TITLE_TAKEN`, `NOTE_NOT_FOUND`
- **Postconditions:** 바뀐 다른 노트가 열려 있으면 Renderer에 알려 다시 불러오게 한다.

### UC-NOTE-005 노트 삭제

- **Main Flow:** 파일을 지우고 색인에서 지운다(그 노트의 AI Job 함께). 다른 노트의 `[[링크]]`는 남고 깨진 링크로 보인다(Q-03: 즉시 삭제).

### UC-NOTE-006 노트 검색 / UC-NOTE-007 연결 / UC-NOTE-008 링크 조회 / UC-NOTE-009 내용 가져오기

규칙은 이전과 같다(BR-NOTE-06·07). 달라진 점:
- 연결: Renderer가 커서에 `[[대상]]` 링크 노드를 넣는다. 대상은 **이름이 보관함에서 유일하면 이름, 아니면 폴더 경로**(`프로젝트/회의록`)로 쓴다.
- 링크 조회: 링크 대상 텍스트를 현재 노트들로 해석해 Outgoing(해석된 것만)과 Incoming을 돌려준다.
- 내용 가져오기: 원본 Markdown을 편집기 문서로 파싱해 넣고, `aiPending`을 제거한다.

## 폴더

### UC-FOLDER-001 폴더 만들기

- **Trigger:** Sidebar `새 폴더`(선택한 폴더 안, 없으면 맨 위)
- **Main Flow:** 이름을 검사하고(BR-FOLDER-01) 폴더를 만든다. 같은 이름이 있으면 거절한다.
- **Failure:** `FOLDER_NAME_INVALID`, `FOLDER_NAME_TAKEN`

### UC-FOLDER-002 폴더 이름 변경

- **Main Flow:** 폴더 이름을 바꾸고, 그 안의 모든 노트의 색인 경로를 갱신한다(ID 유지). 경로로 적힌 링크(`[[옛폴더/노트]]`)는 새 경로로 고친다.

### UC-FOLDER-003 폴더 삭제

- **Trigger:** 폴더 메뉴 `삭제` → 확인(폴더 안 노트 수 표시)
- **Main Flow:** 폴더와 그 안의 모든 파일을 지우고, 색인에서 그 안의 노트를 지운다.

### UC-NOTE-011 노트 이동

- **Trigger:** 노트를 폴더로 끌어 놓기
- **Main Flow:** 파일을 대상 폴더로 옮기고 색인 경로를 갱신한다(ID 유지). 같은 이름이 있으면 거절한다. 경로로 적힌 링크는 고친다.
- **Failure:** `NOTE_TITLE_TAKEN`

## 외부 변경

### UC-VAULT-003 외부 변경 반영

- **Trigger:** 다른 앱이 보관함의 파일·폴더를 바꿈 (감시 → 300ms 모아서 처리)
- **Main Flow:** 바뀐 경로만 색인을 맞추고(UC-VAULT-002), Renderer에 `vault:changed`로 바뀐 노트 ID를 알린다.
- **Renderer:** 목록·트리·검색을 새로 읽는다. 열려 있는 노트가 바뀌었으면: 편집 중이 아니면 조용히 다시 불러오고, 저장 대기 중이면 "다른 곳에서 바뀌었습니다 · 다시 불러오기" 배너를 보인다.

## Business Rules

| ID | 규칙 |
| --- | --- |
| BR-VAULT-01 | 노트 = 보관함 안의 `.md` 파일. `.`으로 시작하는 폴더와 `node_modules`는 제외한다. |
| BR-NOTE-01 | 노트 이름(제목)은 앞뒤 공백 제거 후 1~200자, `\ / : * ? " < > |` 없음, `.`으로 시작하거나 끝나지 않음. |
| BR-NOTE-02 | 본문은 Markdown 문자열, UTF-8 최대 2 MB. |
| BR-NOTE-03 | 링크 대상은 본문의 `[[대상]]`·`[[대상\|별칭]]`에서만 파생된다. 대상 해석: 확장자 없는 경로가 정확히 같은 노트 → 없으면 이름이 같은 노트 중 경로가 가장 짧은 것(대소문자 무시). 자기 자신은 제외. |
| BR-NOTE-04 | 파일 내용이 실제로 바뀐 경우에만 쓰고 수정 시각을 바꾼다. |
| BR-NOTE-05 | 미리보기는 검색용 텍스트 앞 120자(공백 정규화). |
| BR-NOTE-06·07 | 검색·스니펫 규칙은 이전과 같다. |
| BR-NOTE-08 | 검색용 텍스트: Markdown 기호(제목 `#`, 목록 기호, 강조, 인라인 코드 표시)를 빼고, `[text](url)` → text, `[[대상\|별칭]]` → 별칭(없으면 대상), `<span data-ai-pending>` 태그 제거, ```` ```blink-infographic ```` 블록과 앞머리(frontmatter)는 제외. |
| BR-FOLDER-01 | 폴더 이름 규칙은 BR-NOTE-01과 같다. |
