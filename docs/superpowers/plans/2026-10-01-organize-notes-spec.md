# Phase 1 추가 기능 계획: Blink 노트 자동 분류

## 한 줄 요약
Blink 보관함의 노트(`.md` 파일)를 **노트 제목의 뜻만 보고** 비슷한 것끼리 묶어서 폴더를 만들고 이름까지 붙여 정리해 준다. 위층은 넓게, 안으로 들어갈수록 세세하게 나뉜다.

## 기능 흐름
1. **분류하기 버튼 (한 번에 최대 3층)**
   - 대상: 누른 폴더에 바로 있는 노트 + 그 폴더의 「미분류」 노트.
   - 먼저, 이미 있는 하위 폴더에 맞는 노트는 그 폴더로 넣는다 (아래 2번과 같은 계산).
   - 남은 노트끼리 제목의 뜻 기준으로 **최대한 잘게** 묶는다(군집화) → 작은 묶음.
   - **위로 합치기는 AI(gpt)가 정한다.** 작은 묶음들과 그 제목을 보내면, 묶음마다 들어갈 폴더 경로(최대 3층, 예 `공부/Spring`)를 받는다. 같은 경로를 받은 묶음끼리는 한 폴더로 합쳐진다.
     - 합성 노트 100개 결과: 작은 묶음 9개 → `공부/{rust, spring, 자료구조, 파이썬}`, `생활/{기록, 일정}`, `요리/{레시피, 베이킹}`, `운동`.
     - 군집화로 만든 나무를 주고 «살릴 층만 고르기»를 시켜 봤더니, 나무에서 운동과 코딩이 한 갈림길로 묶인 걸 그대로 살려 «운동 안에 학습»이 생겼다. 그래서 위로 합치기는 gpt에게 전부 맡긴다.
     - 코드가 검사한다: 모든 묶음이 정확히 한 번씩, 깊이 1~3, 폴더 이름 규칙. 틀리면 «폴더를 정리하지 못했습니다»로 알리고 아무것도 옮기지 않는다.
   - 새 폴더가 생기면, 형제 폴더 안의 노트 중 **자기 폴더보다 새 폴더의 대표 위치에 더 가까운 노트는 새 폴더로 자동으로 옮긴다.** (처음엔 노트가 적어 넓게 묶였다가, 쌓이면서 더 맞는 폴더가 생기는 경우)
   - 옮기기 전에 미리보기를 보여주고, 사용자가 확인하면 실제로 옮긴다. 옮기지 못한 노트가 있으면 제목을 알려 준다.
   - 더 나누고 싶으면 사용자가 하위 폴더에 들어가서 «분류하기»를 다시 누른다.
   - 「미분류」 폴더 안에는 «분류하기» 버튼이 없다.
2. **새 노트 자동 배치**
   - 언제: Blink에서 만든 노트에 **처음 제목을 붙일 때 한 번**, 또는 바깥의 `.md` 파일을 끌어다 **놓는 순간**. 그 뒤로 제목을 바꿔도 움직이지 않는다.
   - 어디서부터: 노트를 **만든 폴더(끌어다 놓은 폴더)를 맨 위로 보고** 아래로 한 층씩 내려간다. 앱을 처음 열었을 때처럼 선택된 폴더가 없으면 보관함 맨 위부터.
   - 각 층에서: 새 노트와 각 하위 폴더의 **대표 위치**(그 폴더 노트들의 평균 즉 원의 중심점이라고 보면됨) 사이 거리를 잰다. 그 거리가 **그 폴더의 반경**보다 가까우면 그 폴더로 들어간다.
     - 폴더 반경: 기존 노트마다 «자기를 뺀 나머지 노트들의 대표 위치»까지 거리를 재서 가장 먼 값. (자기를 넣고 재면 거리가 작게 나와서 «1·2·3편» 폴더가 «4편»을 거절했다.)
   - 들어갈 하위 폴더가 없으면 **그 층의 「미분류」** 로 간다. 하위 폴더가 아예 없는 폴더면 「미분류」를 만들지 않고 그 폴더에 그대로 둔다.
3. **폴더 이름 붙이기**
   - 위 1번의 폴더 경로를 받을 때 이름도 같이 정해진다 (AI 호출은 분류하기 한 번에 한 번).
   - 이름이 마음에 안 들면 사이드바 폴더 메뉴의 «이름 바꾸기»로 고친다 (Blink에 이미 있는 기능, 링크도 같이 고쳐짐).

## 「미분류」 폴더
- 층마다 생긴다. 예: `공부/`에는 맞는데 `공부/Spring/`, `공부/Rust/` 어디에도 안 맞으면 `공부/미분류/`.
- 실제 폴더로 만든다.

```
보관함/
├─ 공부/
│  ├─ Spring/
│  ├─ Rust/
│  └─ 미분류/
├─ 요리/
└─ 미분류/
```

## 정한 것
- **노트 내용은 안 보고 제목만 쓴다.** 제목은 «인공지능 제대로 모델링하는법», «spring boot 실무 이해 1편»처럼 주제가 드러난다고 가정한다. (Blink는 노트 제목 = 파일 이름)
- **정리 대상은 `.md` 노트만.** 끌어다 놓기도 `.md` 파일만 받는다.
- **제목 비교 방식: 뜻(임베딩).** 제목을 OpenAI `text-embedding-3-large`로 «뜻이 담긴 숫자 목록»으로 바꿔 비교한다.
  - 글자 조각 비교는 «Spring»과 «Rust»가 둘 다 코딩이라는 걸 몰라서 넓은 폴더가 안 생겼다.
  - 작은 모델(`text-embedding-3-small`)로는 넓게 5개로 나눴을 때 큰 주제 정답률 62%, 큰 모델은 88%였다 (합성 노트 100개로 측정).
  - 비용·시간: 제목 100개에 약 $0.00014 (100만 토큰당 $0.13), 응답 약 3초. 결과는 저장하지 않고 누를 때마다 새로 계산한다.
- **묶는 방법:** 누를 때마다 그 폴더 안에서만 k-means를 한 번 돌린다.
- **몇 개로 나눌지(k):** k = 2 ~ max(2, 파일 수 ÷ 2) 범위를 전부 돌려 보고, **실루엣 점수**가 가장 높은 k를 쓴다. (소수점 버림)
  - 실루엣 점수: 각 파일이 자기 묶음에 얼마나 잘 붙어 있는지 -1~1로 잰 점수 (Rousseeuw 1987)
  - 상한 «파일 수 ÷ 2»: 모든 묶음이 2개 이상일 수 있는 가장 큰 k. 여기서는 자연스러운 작은 묶음을 찾는 게 목적이라 넉넉히 둔다. 넓은 위층은 gpt가 합쳐서 만든다.
  - 상한을 √(파일 수 ÷ 2)로 줄여 봤더니 폴더 수가 모자라 억지로 합치다가 Rust가 헬스·러닝과 묶였다 (k-means는 «뜻이 가장 가까운 곳»이 아니라 «전체가 덜 흩어지는 곳»으로 붙인다). 그래서 되돌렸다.
- **억지로 나누지 않는 장치**
  - 파일이 3개 미만이면 분류하지 않는다 (실루엣 점수는 묶음 수가 2 ~ 파일 수−1일 때만 계산됨).
  - 가장 좋은 실루엣 점수도 **0.05** 미만이면 «나눌 만한 묶음이 없어요»라고 알려주고 그대로 둔다.
    - 근거(직접 측정, 상한 «파일 수 ÷ 2»): 관계없는 제목만 모았을 때 0.029~0.032, 주제가 있는 노트는 0.158(노트 100개)~0.603(뚜렷한 두 주제). 잡동사니 16개는 0.060으로 «목록류» 같은 약한 공통점끼리 나뉜다.
    - 논문의 0.51(«쓸 만한 구조», Kaufman·Rousseeuw 1990)은 숫자 몇 개로 된 데이터 기준이라, 짧은 제목에서는 거의 나오지 않는다.
  - 파일 1개짜리 묶음은 폴더로 만들지 않는다.
- **AI가 필요한 곳:** 분류하기·새 노트 자동 배치·끌어다 놓기 모두 임베딩 때문에 AI 설정이 필요하다. OpenAI만 된다. 설정이 없거나 다른 공급자면 «설정에서 OpenAI를 연결해 주세요»라고 알리고 옮기지 않는다.
- **옮기기:** 파일을 직접 옮기지 않고 Blink에 있는 기능을 쓴다.
  - 노트 옮기기 `note:move` — 다른 노트의 `[[링크]]`도 알아서 고쳐 준다.
  - 폴더 만들기 `folder:create`
  - 끌어다 놓은 `.md` 파일은 «보관함으로 복사 → 크기 등 검사 → 원본 지우기» 순서로 가져온 뒤 자동 배치한다. 중간에 실패하면 복사본을 지워 아무것도 옮기지 않은 상태로 둔다.
  - 열려 있어서 옮기지 못한 파일은 «파일을 닫고 다시 넣어 주세요»라고 알리고 원래 자리에 둔다.
- **같은 이름 충돌:** Blink는 같은 폴더에 같은 이름을 허용하지 않으므로, 제목 뒤에 번호를 붙인 뒤(`… (2)`) 옮긴다.
- **위로 합치기와 이름 (gpt):** 분류하기 한 번에 AI 호출 한 번.
  - 작은 묶음 전부(묶음마다 제목 전부)와 지금 폴더 경로를 한 번에 보내서, 묶음마다 폴더 경로(1~3층)를 받는다.
  - **층이 위일수록 보편적으로, 내려갈수록 구체적으로** 짓게 한다. «넓게/좁게»라고만 말하면 애매하므로 층별 이름 예시를 준다: 1층 예 «공부, 요리, 운동, 업무, 생활» / 2층 예 «코딩, 영어, 수학» / 3층 예 «Spring, Rust, 파이썬». 지금 폴더가 2층이면 받는 경로의 첫 칸은 3층 넓이다.
  - 규칙: 같은 분야는 같은 위층 아래로, 하위 폴더를 하나만 갖게 되는 폴더는 만들지 않기, 폴더 이름은 한 단어·«미분류» 금지.
  - 답은 정해진 형식(JSON, 예 `{"assignments": [{"group": "G1", "path": ["공부", "Spring"]}]}`)으로만 받는다.
  - 비용·시간(노트 100개, 작은 묶음 9개): 입력 약 1,150토큰·출력 약 140토큰 ≈ $0.0015, 응답 약 2.5초 (`gpt-5.4-mini` 100만 토큰당 입력 $0.75·출력 $4.5).
  - AI는 Blink 설정에서 «사용 중»으로 고른 것을 그대로 쓴다: OpenAI `gpt-5.4-mini`.

## 스택 (Blink 위에 붙임)
| 부분 | 쓰는 것 |
|---|---|
| 앱 | Blink 그대로 (Electron + React + TypeScript) |
| 화면 | 사이드바 폴더에 «분류하기» 버튼, 미리보기 창, `.md` 끌어다 놓기 |
| 제목 → 숫자 | OpenAI `text-embedding-3-large` (Blink의 AI 연결에 «임베딩» 추가) |
| k-means | 직접 작성 (유사도 표로 계산 — `ml-kmeans`는 노트 100개에 9.5초 걸려 쓰지 않음) |
| 실루엣 점수 | 직접 작성 |
| 노트·폴더 옮기기 | Blink의 `note:move`, `folder:create` |
| 끌어다 놓은 파일 위치 읽기 | Electron `webUtils.getPathForFile` |
| 위로 합치기·폴더 이름 AI | Blink의 AI 연결 (OpenAI `gpt-5.4-mini`, JSON으로 폴더 경로 받기) |
| 코드 위치 | Blink 설계 규칙대로 `src/main/<기능이름>/` 새 폴더 |
