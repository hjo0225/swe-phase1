# Phase 1 추가 기능 계획: Blink 노트 자동 분류

## 한 줄 요약
Blink 보관함의 노트(`.md` 파일)를 **노트 제목만 보고** 비슷한 것끼리 묶어서 폴더를 만들고 이름까지 붙여 정리해 준다.

## 기능 흐름
1. **분류하기 버튼 (한 번 = 한 층)**
   - 대상: 누른 폴더에 바로 있는 노트 + 그 폴더의 「미분류」 노트.
   - 먼저, 이미 있는 하위 폴더에 맞는 노트는 그 폴더로 넣는다 (아래 2번과 같은 계산).
   - 남은 노트끼리 제목 기준으로 묶는다(군집화). 묶음 하나가 새 하위 폴더 하나가 된다.
   - 새 폴더가 생기면, 형제 폴더 안의 노트 중 **자기 폴더보다 새 폴더의 대표 위치에 더 가까운 노트는 새 폴더로 자동으로 옮긴다.** (처음엔 노트가 적어 넓게 묶였다가, 쌓이면서 더 맞는 폴더가 생기는 경우)
   - 옮기기 전에 미리보기를 보여주고, 사용자가 확인하면 실제로 옮긴다.
   - 더 나누고 싶으면 사용자가 하위 폴더에 들어가서 «분류하기»를 다시 누른다.
   - 「미분류」 폴더 안에는 «분류하기» 버튼이 없다.
2. **새 노트 자동 배치**
   - 언제: Blink에서 만든 노트에 **처음 제목을 붙일 때 한 번**, 또는 바깥의 `.md` 파일을 끌어다 **놓는 순간**. 그 뒤로 제목을 바꿔도 움직이지 않는다.
   - 어디서부터: 노트를 **만든 폴더(끌어다 놓은 폴더)를 맨 위로 보고** 아래로 한 층씩 내려간다. 앱을 처음 열었을 때처럼 선택된 폴더가 없으면 보관함 맨 위부터.
   - 각 층에서: 새 노트와 각 하위 폴더의 **대표 위치**(그 폴더 노트들의 평균 즉 원의 중심점이라고 보면됨) 사이 거리를 잰다. 그 거리가 **그 폴더의 대표 위치에서 가장 멀리 있는 기존 노트까지의 거리**보다 가까우면 그 폴더로 들어간다.
   - 들어갈 하위 폴더가 없으면 **그 층의 「미분류」** 로 간다. 하위 폴더가 아예 없는 폴더면 「미분류」를 만들지 않고 그 폴더에 그대로 둔다.
3. **폴더 이름 붙이기**
   - AI가 노트 제목 목록을 보고 폴더 이름을 짓는다.
   - 사용자가 화면에서 이름을 고칠 수 있다.

## 「미분류」 폴더
- 층마다 생긴다. 예: `공부/`에는 맞는데 `공부/Spring/`, `공부/Rust/` 어디에도 안 맞으면 `공부/미분류/`.
- 실제 폴더로 만든다.

```
보관함/
├─ 공부/
│  ├─ Spring/
│  ├─ Rust/
│  └─ 미분류/
├─ 요리/
└─ 미분류/
```

## 정한 것
- **노트 내용은 안 보고 제목만 쓴다.** 제목은 «인공지능 제대로 모델링하는법», «spring boot 실무 이해 1편»처럼 주제가 드러난다고 가정한다. (Blink는 노트 제목 = 파일 이름)
- **정리 대상은 `.md` 노트만.** 끌어다 놓기도 `.md` 파일만 받는다.
- **묶는 방법:** 누를 때마다 그 폴더 안에서만 k-means를 한 번 돌린다.
- **몇 개로 나눌지(k):** k = 2 ~ (파일 수 ÷ 2) 범위를 전부 돌려 보고, **실루엣 점수**가 가장 높은 k를 쓴다. (소수점 버림, 2보다 작으면 2)
  - 실루엣 점수: 각 파일이 자기 묶음에 얼마나 잘 붙어 있는지 -1~1로 잰 점수 (Rousseeuw 1987)
  - 범위 상한 «파일 수 ÷ 2»: 모든 묶음이 2개 이상일 수 있는 가장 큰 k. 이보다 크면 1개짜리 묶음이 반드시 생기는데, 1개짜리 묶음은 폴더로 만들지 않으므로 시험할 의미가 없다.
  - 속도(가짜 제목으로 측정): 100개 1.3초, 200개 5.8초.
- **억지로 나누지 않는 장치**
  - 파일이 3개 미만이면 분류하지 않는다 (실루엣 점수는 묶음 수가 2 ~ 파일 수−1일 때만 계산됨). 나눌지 말지는 실루엣 점수가 정한다.
  - 가장 좋은 실루엣 점수도 0.51 미만이면 «나눌 만한 묶음이 없어요»라고 알려주고 그대로 둔다. (0.51 이상 = «쓸 만한 구조», Kaufman·Rousseeuw 1990) => 간단하게 해봤는데 0.51은 커녕 0.17이 가장 높은 숫자가 나옴 이건 만들고 우리가 직접 분류하면서 실루엣 점수를 우리가 정해야할듯 아마 0.51은 높은 숫자인듯?
  - 파일 1개짜리 묶음은 폴더로 만들지 않는다.
- **옮기기:** 파일을 직접 옮기지 않고 Blink에 있는 기능을 쓴다.
  - 노트 옮기기 `note:move` — 다른 노트의 `[[링크]]`도 알아서 고쳐 준다.
  - 폴더 만들기 `folder:create`
  - 끌어다 놓은 `.md` 파일은 보관함에 넣으면 Blink의 바깥 변경 감지가 목록에 넣고, 그 뒤 `note:move`로 제자리에 보낸다.
  - 열려 있어서 옮기지 못한 파일은 «파일을 닫고 다시 넣어 주세요»라고 알리고 원래 자리에 둔다.
- **같은 이름 충돌:** Blink는 같은 폴더에 같은 이름을 허용하지 않으므로, 제목 뒤에 번호를 붙인 뒤(`… (2)`) 옮긴다.
- **이름 붙이기:** 분류하기 한 번에 AI 호출 한 번.
  - 지금 폴더 이름(부모)과 새로 생길 형제 묶음 전부의 노트 제목을 한 번에 보내서, 이름을 동시에 받는다.
  - **층이 위일수록 보편적으로, 내려갈수록 구체적으로** 짓게 한다. «넓게/좁게»라고만 말하면 애매하므로 두 가지를 같이 준다.
    1. **층별 이름 예시:** 1층 예 «공부, 요리, 운동, 업무» / 2층 예 «코딩, 영어, 수학» / 3층 예 «Spring, Rust, 파이썬». 이번에 지을 층을 알려주고 그 층 예시와 같은 넓이로 짓게 한다.
    2. **지금 경로:** 예 «공부 > 코딩». 새 이름이 이 경로 아래에 맞는 하위 범주여야 한다.
  - 규칙: «한 단어, 이번 층 예시와 같은 넓이로, 형제끼리 겹치지 않게».
  - 답은 정해진 형식(JSON, 예 `{"A": "Spring", "B": "Rust"}`)으로만 받는다.
  - 형제 묶음과 다른 점으로 이름을 짓는 원리는 정보검색 교과서의 «차별 라벨링»(Manning 외 2008)에 해당한다.
  - AI는 Blink 설정에서 «사용 중»으로 고른 것을 그대로 쓴다: OpenAI `gpt-5.4-mini`.

## 스택 (Blink 위에 붙임)
| 부분 | 쓰는 것 |
|---|---|
| 앱 | Blink 그대로 (Electron + React + TypeScript) |
| 화면 | 사이드바 폴더에 «분류하기» 버튼, 미리보기 창, `.md` 끌어다 놓기 |
| 제목 → 숫자 | 글자 조각 비교(TF-IDF) 직접 작성 |
| k-means | `ml-kmeans` (npm) |
| 실루엣 점수 | 직접 작성 |
| 노트·폴더 옮기기 | Blink의 `note:move`, `folder:create` |
| 끌어다 놓은 파일 위치 읽기 | Electron `webUtils.getPathForFile` |
| 폴더 이름 AI | Blink의 AI 연결 (OpenAI `gpt-5.4-mini`) |
| 코드 위치 | Blink 설계 규칙대로 `src/main/<기능이름>/` 새 폴더 |
